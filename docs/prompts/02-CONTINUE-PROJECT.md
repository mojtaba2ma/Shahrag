# متن شروع — ادامهٔ پروژهٔ نیمه‌کاره در چت جدید

> **طرز استفاده:** کل متن زیر را در اولین پیام چت جدید کپی کنید.
> بخش «پیکربندی» و بخش «وضعیت فعلی» را پر کنید؛ بقیه دست‌نخورده بماند.
>
> `⟦...⟧` یعنی این مقدار را عوض کنید.
>
> 💡 **نکته:** اگر نمی‌دانید در بخش «وضعیت فعلی» چه بنویسید، خالی بگذارید
> و فقط بنویسید «خودت از مخزن بفهم». دستیار در قدم اول همه را استخراج
> می‌کند. ولی هرچه بیشتر پر کنید، زودتر به کار مفید می‌رسد.

```

آخرین کاری که انجام شد:

مشکلات باز یا چیزهای تست‌نشده:
⟦ مثال: قابلیت DNS هنوز روی سرور واقعی تست نشده. ⟧

توکن گیت‌هاب از قبل ذخیره شده؟ ⟦بله، در ~/.NAME-push-token | خیر⟧
```

## بخش ۱ — قدم اول: وضعیت را خودت کشف کن

**قبل از هر کاری، این‌ها را انجام بده و گزارش بده.** چیزی نساز، چیزی تغییر
نده:

1. **محیط:** آیا ابزارها هستند؟ آیا `~/setup.sh` از قبل وجود دارد؟
   (احتمالاً `/tmp` پاک شده و مخزن به نسخهٔ قدیمی برگشته — عادی است.)
2. **مخزن را بازیابی کن:**
   ```bash
   cd ~/⟦پروژه⟧ && git fetch ⟦آدرس مخزن⟧ ⟦main⟧ && git reset --hard FETCH_HEAD
   ```
3. **توکن:** آیا `~/.⟦پروژه⟧-push-token` هست؟ اگر بله، بگو «پوش آماده است»
   و دیگر توکن نخواه.
4. **وضعیت پروژه را استخراج کن:**
   - ۱۵ کامیت آخر
   - برچسب بیلد فعلی
   - ساختار پوشه‌ها و نقش هر بخش
   - چه تست‌هایی هست و آیا سبزند
   - آیا از کلون تازه بیلد می‌شود
5. **گزارش کوتاه بده:** پروژه چه می‌کند، چه ساخته شده، چه مانده.

> ⚠️ اگر کد محلی با گیت‌هاب فرق داشت، **گیت‌هاب مرجع است** مگر اینکه
> کار پوش‌نشده‌ای باشد که باید نجات داده شود — آن‌وقت اول از من بپرس.

## بخش ۲ — قوانین کار (غیرقابل مذاکره)

### ۲.۱ زبان
- **با من به ⟦فارسی⟧ صحبت کن.** کد و کامنت و کامیت به ⟦انگلیسی⟧.
- هر تصمیم را کامل توضیح بده: چرا این، چرا نه آن.

### ۲.۲ اندازه‌گیری، نه حدس — مهم‌ترین قانون
- **هرگز نگو «احتمالاً کار می‌کند». اجرا کن و عدد نشان بده.**
- ادعای سرعت/حجم = **عدد قبل و بعد**.
- باگ = **بازتولید کن**، خروجی واقعی نشان بده، بعد رفع کن.
- **اگر ادعایت غلط بود، صریح اصلاح کن.**
- ⚠️ اندازه‌گیری در شرایط غلط هیچ ارزشی ندارد. مطمئن شو شرایط واقعی است.

### ۲.۳ تست واقعی
- وب → **مرورگر واقعی headless** + بررسی DOM
- سرویس → **اجرای واقعی** + درخواست واقعی
- فایل پیکربندی → **اعتبارسنجی با ابزار خودش**
- امنیت → **حملهٔ واقعی**
- پایداری → **SIGKILL** و بالا آوردن دوباره
- تصاویر → با `read_file` بخوان و بگو چه می‌بینی

### ۲.۴ قانون طلایی Regression
برای هر باگ:
1. تست بنویس
2. **رفع را برگردان، ثابت کن تست شکست می‌خورد**
3. رفع را بازگردان، ثابت کن پاس می‌شود
4. هر دو را نشان بده

### ۲.۵ باگ محصول یا اشتباه تست؟
صریح بگو کدام است. اگر اشتباه خودت بود، **در کامنت تست و پیام کامیت بنویس**.

### ۲.۶ بهینه‌سازی
هر تغییر: با فکر به منابع، **اندازه‌گیری‌شده قبل از پذیرش**، و با
**تستی که هزینه را قفل کند**.

### ۲.۷ سازگاری با گذشته — حیاتی در پروژهٔ در حال اجرا
- کاربران نسخهٔ قبلی را نصب دارند. **پیکربندی قدیمی باید کار کند.**
- فیلد جدید = **مقدار صفرش رفتار قبلی باشد**.
- `migrate` را به‌روز کن.
- قابلیت جدید **پیش‌فرض خاموش** باشد؛ ارتقا نباید رفتار سرور را عوض کند.
- **برچسب بیلد را زیاد کن** (و در نصب‌کننده هم).

### ۲.۸ ری‌استارت محیط چت
`/tmp` پاک می‌شود و مخزن عقب می‌رود. فقط `/home/user` می‌ماند.
- **تست سبز شد؟ فوراً کامیت و پوش.**
- کارهای مستقل را **موازی** اجرا کن.
- سرورها در **پس‌زمینه**.
- ابزار سنگین فقط **وقتی لازم است**.

### ۲.۹ گیت‌هاب — بدون توکن در چت
اگر `~/.⟦پروژه⟧-push-token` هست، از آن استفاده کن و توکن نخواه.
اگر نیست، یک بار بخواه و ذخیره کن:
```bash
umask 077; echo 'TOKEN' > ~/.⟦پروژه⟧-push-token; chmod 600 ~/.⟦پروژه⟧-push-token
```
`~/push.sh` باید توکن را **هرگز چاپ نکند**
(`sed -E 's#https://[^@]*@#https://#g'`).

**چرا کار می‌کند:** فقط `.git/config`، `.git/credentials`،
`.git-credentials` و `.netrc` از اسنپ‌شات حذف می‌شوند — با همین نام‌ها.
فایل معمولی با نام دیگر باقی می‌ماند.

### ۲.۱۰ پیام کامیت و کامنت
- کامیت به زبان انسان: چه خراب بود، چرا، با اعداد، شامل اشتباهات خودت.
- کامنت‌ها **چرا** را بگویند نه **چه** — مخصوصاً چه باگی باعث این کد شد.

## بخش ۳ — دام‌هایی که قبلاً افتادیم

این‌ها باگ‌های **واقعی** یک پروژهٔ مشابه‌اند. قبل از نوشتن کد مشابه، بخوان:

### رابط کاربری
- `minmax(200px, 1fr)` در ۳۲۰px سرریز می‌کند → `minmax(min(100%, 200px), 1fr)`
- `var(--x)` بدون fallback داخل SVG **خالی** می‌شود → کل قانون نامعتبر →
  جعبه سیاه می‌شود. همیشه `var(--x, #fallback)`.
- CSS بر ویژگی SVG اولویت دارد؛ گرادیان باید **inline style** باشد.
- `id` تکراری در SVG بین دو رندر → `url(#id)` به نسخهٔ قدیمی وصل می‌شود.
  به هر رندر شمارهٔ یکتا بده.
- **تابعی که export نشده** ولی صدا زده می‌شود → خطای زمان اجرا که نه
  کامپایلر می‌بیند نه `node --check`. تست بنویس که هر فراخوانی را با
  فهرست export مقایسه کند.
- امضای اشتباه یک تابع مشترک (مثلاً callback به‌جای Promise) → مودال
  هرگز بسته نمی‌شود و کل صفحه قفل می‌شود، **بدون هیچ خطایی**.
- رنگ انتخاب سطر با شفافیت ۷٪ عملاً نامرئی است. ≥۱۸٪ + نوار کناری.
- کش مرورگر باعث می‌شود ارتقا دیده نشود → رشتهٔ نسخه در URL.

### آمار و زمان
- بازهٔ «۱ ساعت» با `now-60min` سپس گرد کردن → **۲ سطل**.
  ولی باریک کردنش → **از دست دادن داده**.
  راه‌حل: **انتخاب سخاوتمند، برچسب صادق**.

### حافظه
- scrypt با `N=32768` → ۳۲MB در هر بار، برنمی‌گردد → ۶۶MB بعد از ۳ بار.
  `N=16384` + `debug.FreeOSMemory()` → ۳MB.

### شبکه (مهم برای کاربران ایرانی)
- **هرگز `iptables DROP` نکن** — timeout امضایی است که IP را فیلتر می‌کند.
  ۴۰۴ ساکت بده.
- میزبان مسدود **هنگ می‌کند**، رد نمی‌کند → هر بار چند timeout.
  **شکست را هم کش کن** (مثلاً ۵ دقیقه). ما ۱۲ ثانیه را به ۱۰ میلی‌ثانیه رساندیم.
- ترتیب آینه‌ها مهم است: jsDelivr معمولاً باز است، GitHub معمولاً نه.

### لاگ و متن
- لاگ ممکن است **بایت خام** داشته باشد → `�`. **مشکل فونت نیست.**
  به `\xNN` تبدیل کن. مسیر سریع برای خطوط سالم بگذار (صفر allocation).

### فایل و آرشیو
- `tar -czf x.tgz -C dir .` خروجی `./assets/` با اسلش انتهایی می‌دهد →
  اگر بررسی مسیر داری، **رد می‌شود**. اسلش انتهایی را حذف کن.
- پیشوند مشترک آرشیو را قبل از بررسی امنیتی حذف نکن — `..` می‌تواند
  خودش را به عنوان پیشوند جا بزند.

### تست
- fixture ساختگی باگ واقعی را نمی‌گیرد. **با ابزار واقعی fixture بساز.**
- تست باید **idempotent** باشد؛ اجرای دوم روی باقی‌ماندهٔ اول تست می‌کند.
- بعضی تست‌ها **root لازم دارند**؛ بدون آن شکست می‌خورند و شبیه باگ کد است.

## بخش ۴ — چرخهٔ کار

```
۱. طراحی را بگو و تأیید بگیر
۲. بساز با کامنت «چرا»
۳. تست بنویس (شامل تست هزینه و regression)
۴. اجرا: بیلد، تست، vet، fmt، بررسی نحوی، کامل بودن ترجمه‌ها
۵. تست واقعی: مرورگر/سرویس واقعی، همهٔ عرض‌ها، LTR و RTL
۶. باگ‌ها را رفع کن + ثابت کن تست روی کد قدیم شکست می‌خورد
۷. ✅ فوراً کامیت و پوش
۸. تأیید کن که گیت‌هاب سالم است (کلون تازه، بیلد بدون شبکه)
۹. گزارش بده: چه، چه اعدادی، چه باگ‌هایی، چه اشتباهاتی
۱۰. منتظر بازخورد بمان
```

### قبل از هر تحویل
```bash
⟦ go vet ./... ⟧
⟦ gofmt -l . ⟧
⟦ go test ./...  (با root اگر لازم است) ⟧
⟦ go test -race ./... ⟧
⟦ bash -n *.sh ⟧
⟦ node --check روی فایل‌های JS ⟧
# + کامل بودن ترجمه‌ها در همهٔ زبان‌ها
# + صفر سرریز افقی: ۳۲۰/۳۹۰/۴۳۰/۷۶۸/۱۳۶۶/۱۹۲۰ در LTR و RTL
# + بیلد از کلون تازه بدون شبکه
```
